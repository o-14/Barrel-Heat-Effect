the same byte surgery used in `tools\collapse_nif_shape_geometry.py` and

## What to ask Ghidra

Project: `<local-path>`
Program: `Fallout4.exe` 1.10.163 OG, image base `0x140000000`, 199,088 functions,
16,029 named, CommonLibF4 types imported.

1. **`TESObjectREFR::ApplyArtObject`** - `REL::ID 357908`. The signature in
   `CommonLibF4/include/RE/Bethesda/TESObjectREFRs.h:696` is:

   ```cpp
   ModelReferenceEffect* ApplyArtObject(BGSArtObject* a_art, float a_time = -1.0f,
       TESObjectREFR* a_facingRef = nullptr, bool a_attachToCamera = false,
       bool a_inheritRotation = false, NiAVObject* a_3D = nullptr,
       bool a_interfaceEffect = false);
   ```

   **The question:** is `a_3D` honoured as the attach root, or is it overwritten by
   `ReferenceEffect::GetAttachRoot()` (which defaults to `ref->Get3D()`, the
   third-person model)? If it is honoured, can it be a node in the first-person graph?

2. **`EquippedWeaponData::fireNode`** (`Actor.h:305`, offset `0x30`). Who writes it, and
   is it the first-person or third-person weapon instance? Is there a first-person
   equivalent reachable from the player's middle-high process data?

3. **`ModelReferenceEffect` lifetime** - what ends it cleanly? `BSTempEffect::lifetime`,
   `ReferenceEffect::finished`, or a `ProcessLists` call? Also what
   `ReferenceEffect::Update3D` / `SwitchAttachedRoot` do on weapon or view change.

4. **`MuzzleFlash`** - only forward-declared in CommonLibF4 (`Actor.h:76`). Recover the
   layout from RTTI. Unlocks the Route B fallback of driving the engine's own muzzle
   flash object.

5. **Verify `REL::ID 1452334`** (`HEAT_PROJECTILE_LAUNCH_ID` in `ProjectileEmitter.h`)
   really is the projectile launch function, and confirm `357908` for `ApplyArtObject`.
